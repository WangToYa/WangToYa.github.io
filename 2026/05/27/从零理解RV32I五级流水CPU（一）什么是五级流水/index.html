从零理解RV32I五级流水CPU（一）什么是五级流水

前言

最近开始正式学习 RV32I 五级流水 CPU。
之前也写过一些 Verilog 小项目，比如：

  • UART
  • 数码管
  • 状态机
  • FPGA 小系统

但真正看到一个完整 CPU 项目时，
还是有一种：

“原来 CPU 真的是这样工作的”
的感觉。

这个系列主要记录我学习五级流水 CPU 的过程。

一方面是为了整理自己的理解，

能看到自己是怎么一步一步真正理解 CPU 的。

目前我学习的项目是一个基于 Verilog 实现的 RV32I 五级流水 CPU，
项目中包含：

  • Pipeline（流水线）
  • Forwarding（数据转发 / 旁路）
  • Hazard Detection（冒险检测 / 冲突检测）
  • Branch（分支 / 跳转）
  • Stall（阻塞 / 暂停）

这些以前只在课本里见过的东西。

什么是流水线（Pipeline）

在刚开始学 CPU 的时候，
我一直有一个问题：

为什么 CPU 要设计成“流水线”？

后来才发现，
核心原因其实很简单：

为了提高吞吐率。

单周期 CPU 的问题

最开始的 CPU 通常是单周期 CPU。

也就是说：

例如：

第一条指令必须完全执行结束，
第二条才能开始。

这样会导致：

CPU 很多时间都在“等待”。

例如：

  • ALU 工作时，访存模块空闲
  • 访存时，ALU 又空闲

硬件利用率很低。

流水线的思想

后来工程师想到：

能不能像工厂流水线一样，
让多个阶段同时工作？

例如：

如果所有步骤串行执行：

效率会很低。

但如果：

  • 第一件在烘干
  • 第二件开始洗衣

整个效率就会高很多。

CPU 流水线其实也是同样的思想。

我第一次真正理解流水线的时候

以前我一直以为：

“CPU 很神秘”

但真正开始看项目后，
我发现：

CPU 本质上其实也是：

  • 模块
  • 数据流
  • 状态
  • 时序

只是复杂度更高。

五级流水最重要的一点，
其实是：

“让多个阶段并行工作”

而不是让一条指令跑得更快。

这一点我一开始其实一直理解错了。
